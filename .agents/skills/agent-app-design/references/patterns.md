# 設計模式與證據判斷

研究基準日：2026-10-02。以下是決策方法，功能與名稱仍需在使用時更新。

| 模式 | 想解決的問題 | 適用條件 | 常見誤用 |
| --- | --- | --- | --- |
| 專案／對話／任務分層 | 找回一件工作 | 系統有可驗證的歸屬 ID | 用網頁目前開啟的聊天猜測全部活動歸屬 |
| 需要你處理的佇列 | 降低等待與誤批準 | 狀態和實際核准請求一致 | 只顯示紅點、每張卡重複警語 |
| 計畫 → 執行 → 檢查 | 區分意圖和實際成果 | 有明確階段與退出條件 | 把模型說「完成」當測試通過 |
| 漸進揭露 | 讓主畫面保持短小 | 細節可讀取且不影響主要決策 | 把有效授權、風險或錯誤全部摺疊 |
| 工作區隔離 | 平行工作與版本對齊 | 系統真的控制 worktree／執行環境 | 把起始 cwd 或程序群組叫作 sandbox |
| 成果檢查 | 將動作連回可驗證結果 | 有版本、diff、exit code 或 artifact | 用百分比／勾號模擬未知的進度 |
| 上下文包接力 | 換 Agent 時減少重新說明 | 使用者審閱內容並重新建立權限 | 把摘要匯入當成原對話、記憶、授權或執行程序搬移 |
| 不確定結果的對帳 | 斷線後避免重跑副作用 | request ID 可去重且有查詢狀態 | 逾時後換 ID 自動重送命令 |

對每項模式記錄 surface、來源 URL／檔案、日期、觀察類型和 confidence。說明官方宣傳畫面能證明可見布局，不能證明全部互動、鍵盤操作、執行成功或目前安裝版本。

需要更新官方資料時，從 [OpenAI Codex app 文件](https://developers.openai.com/codex/app/)、[Claude Code Desktop 文件](https://code.claude.com/docs/en/desktop) 和 [Claude Code CLI 互動模式](https://code.claude.com/docs/en/interactive-mode) 開始；記錄任何重新導向。避免複製完整說明書進 skill。

窄版側欄通常採一個主要閱讀區；桌面 app 的三欄布局只在空間足夠、使用者需要同時比較時才值得移用。驗收應用真實可見狀態：長專案名、多件核准、空白、失敗、斷線、結果逾期與長 diff。

驗收失敗恢復時，安排「操作已提交但回應遺失」與「查詢仍顯示原狀態」兩種情境。成功取得目錄不等於原操作已完成；只有原請求、不可變身份與對應結果才能消除不確定。不同狀態使用獨立但不重複的公告；讀屏效果需實際驗證。

新建設定的名稱與 ID 不足以證明身份，對帳須涵蓋完整配置。取消串流後不交付排隊資料；正常 EOF 也要停用操作。歷史內容、版本及來源名稱不因解除掛載或失敗重讀而改寫；成功且身份匹配才改標為目前內容，歷史名稱不授予操作能力。

切換成果時，用已載入 A、B 延遲、A 晚回覆與錯 ID 回覆驗收。內容、錯誤、取消狀態都要綁原目標，render 當下不能把舊內容配新標題；分頁 cursor 必須在身份確認後才採用。卸載後才取得的 object URL 仍須回收。載入與錯誤各保留一份短提示。

可讀性驗收包含 placeholder、錯誤正文、成功標籤、截斷提示與鍵盤焦點，不能只量正常正文。未完成資訊不是 disabled control，整節點 opacity 仍要合成對比。確認真正套用的 selector、主題與祖先背景；gradient／filter 未解時保留限制，對比門檻用未四捨五入值。窄版改善靠字級、換行與點選區，不靠新增說明。減少動態要檢查高 specificity 與偽元素；強制 CSS 分支不證明真偏好、JS media 事件或 iframe 的獨立樣式。

比較人工整理與 Agent 接續時，兩種方式使用同等難度且相同事實的材料，要求相同最低資訊。主持控制、預填答案與前輪狀態不能影響參與者；合成 API 不可把任意路徑當支持檔案，或漏掉完成／未驗欄位來製造速度優勢。新入口除了切換面板，還須驗證必要資料真的載入；Agent 的工程互動不計為真人成果。
