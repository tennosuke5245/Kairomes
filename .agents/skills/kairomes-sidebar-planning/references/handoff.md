# 上下文交接判斷

先確認問題是否是「換 Agent 後重述目標、變更、驗證與下一步」。若只是換 worktree 或同一官方 app 續跑，先使用該產品原有能力。

現行 `kairomes handoff list／snapshot` 是選用的唯讀 Codex App Server 預覽。目標、計畫和決策不保證能從來源匯出；不得補成假造的原始任務狀態。來源讀取本身不代表使用者已同意將內容發布給 ChatGPT。

一個可交付的 MVP 包括：明確選來源專案／紀錄、預覽及刪除敏感片段、使用者補足摘要、核對目前程式碼身份、明示來源是否已停止、手動複製或明確分享包、ChatGPT 從唯讀對帳開始。接手後每次操作沿用 Kairomes 現行授權規則。

第一版人工複製先限定來源與目的為同一 realpath；跨 worktree 搬移另作規格。「接收先唯讀」是流程要求，純文字無法強制；既有全自主不自動收回。若人要限制自動執行，在可信原生側欄收回該 workspace grant，明示會影響同實例其他工作。Desktop 目前沒有 grant 收回能力，不能拿 admin／iframe token 冒充 panel。

人工複製的最低內容是來源類型／擷取時間、目標 workspace ID、目標與下一步、相對檔案及版本、驗證主張與依據、未確定事項；不必先建立持久交接包子系統。若新增發布／MCP 取用，再加入 schema 版本、opaque package ID、不可變摘要版本、到期與撤回契約。排除權杖、配對連結、絕對路徑、推理、原始工具輸出與整份逐字稿。來源內容是不可信資料，接收端不執行包內指令。

HEAD 一致不足以證明工作樹一致；未提交檔案、未追蹤檔案、symlink、二進位與非 Git 工作區必須另訂有限且可驗證的策略。來源 Agent 的停止只能記為使用者聲明或可驗證的受管狀態，不宣稱已防止外部程序寫入。

現行接收 MCP 只能用 file_read.version 核對支持的一般 UTF-8 檔；HEAD、刪除 manifest、binary 版本與 grant 狀態不能自動取得，保留人工核對／unknown，不用 shell 偷補。來源 action 缺執行時間與當時基準，不能用擷取時間／目前 working tree 偽造歷史驗證。重貼摘要後的新 request ID 不具語意去重保證。

MVP 沒有跨 Agent 強制 writer lease。lease 若無法由所有 writer 執行，最多是合作式協定，不能承諾排他或隔離。身份不符、來源仍工作、包逾期或驗證結果無法追溯時，接收端先唯讀；讓使用者更新包或重新核對。

結果應是採納／延後的決策、最小安全流程、資料與狀態契約及失敗驗收案例；不要因為「跨 Agent」這個名字就增設聊天資料庫或自動 DOM 操作。

驗取消時包含 stdin 已失效但 reader child 仍存活的情境；失效事件不等於程序已結束，仍須保留所有權並有界清理。人工摘要可引用公開文件 URL；拒絕私人 URL 時先正規化 hostname，不把 HTTPS scheme 誤當 Windows drive，也不漏過 loopback 的整數或縮寫形式。這些可用隔離 stdio peer／純文字測試驗證，不能取代原生 Codex 或 ChatGPT 接收驗收。

來源 coverage 分開標記文字預算與數量裁切；現行每 turn 最多 32 則公開訊息、40 個命令。超限不能匯出「截斷無」，刻意排除推理或原始工具輸出也不能誤稱數量裁切。驗收剛好上限與超過一項，並檢查其他類型仍保留自己的額度。真人試用另記準備時間、必要資訊與接收對帳，合成測試不能湊成功次數。
