# D10 後續使用研究

狀態：**測試規格已準備，尚未招募或量測**。接續[開發計畫](development-plan.md)第 2 節，驗證側欄判斷與 H1 是否減少重新說明成本。工程回歸與合成瀏覽器畫面不計為真人成功次數。

2026-10-03 調整定位：本文件是選用的後續研究方案，五人試用與計時不作為本輪程式碼開發的完成前提。一般使用者直接使用 Kairomes，回報找不到入口、文字看不懂或操作卡住即可；不需要先完成這份主持腳本。以下材料供開發者與未來研究使用。

免安裝預覽屬內部工程工具，不加入產品功能或要求使用者操作。基本可讀性與鍵盤操作仍屬介面品質；原生側欄、宿主與交接實際路徑的相容檢查另記，未驗證的項目不能宣稱已通過。

使用者目前選擇先不安裝 Extension。本輪準備文件與記憶體測試材料；不載入 Extension、不配對真工作台、不讀私人 Codex 歷史，也不登入 ChatGPT 代送內容。需要原生環境的階段保留待辦。

## 1. 兩種環境分開計分

| 階段 | 用途 | 材料 | 證據限制 |
| --- | --- | --- | --- |
| A：合成分頁試用 | 判斷入口、文字密度、成果身份與未決狀態 | repository 純合成 preview、虛構檔案／命令／圖片，控制由主持人操作 | 不證明原生 sidePanel、真配對、真 MCP 程序、剪貼簿或 ChatGPT 接收 |
| B：受控原生接續 | 驗證真側欄、宿主、權限核對與人工交付 | 後續明確允許的新建測試專案、合成 Codex 對話與測試帳號 | 不證明任意工作區相容、排他接管或接收 Agent 被強制唯讀 |

同一人可以參與兩階段，但 B 另記平台、app／瀏覽器版本與資料來源。A 完成不解除 B 的環境前置條件。預覽使用 `bun run scripts/preview-sidebar.ts`，分頁位址取終端當次列出的隨機 port，不保存於報告。

## 2. 人員、比較方式與準備

側欄旅程以五名測試者為第一輪。先完成未提示的任務，再回答判斷問題；接受位置提示的項目記「有協助」，不計獨立完成。任務前不解釋按鈕、狀態或權限答案。

H1 以五次受控接續評估準備時間，優先由五人各做一次。若同一人重複五次，標記為重複執行，不能寫成五名使用者驗證。資料變體與呈現次序先固定，不重複練習同一答案來湊足成功次數。

比較 H1 與人工整理時，使用 alpha／beta 兩組同等難度的合成任務（資料組不等於環境階段）：各有一個目標、兩項完成事項、一項未驗證事項、兩個相關文字檔與一個版本差異。前三人先做人工整理、後做 H1；後兩人反序。第二次換資料組。兩種方式要求相同的最低資訊，不能把漏項的短摘要評為更快。

| 準備項目 | 主持人確認 |
| --- | --- |
| 平台 | 階段、OS、app／瀏覽器版本、viewport；縮放與輔助工具另記 |
| 資料 | 全部合成；命令不啟動主機程序；沒有真 token、配對連結、私人路徑或對話 |
| 狀態 | 每項重設；測試者看不到測試控制或答案；失敗與延遲由主持人觸發 |
| 記錄 | 匿名編號，僅時間、步驟、協助、判斷與錯誤；不錄聊天全文、工作區內容或螢幕影片 |
| 結束 | 關閉合成分頁與服務；B 只清理允許的測試資料，不碰使用者專案 |

### 免安裝材料與主持控制

主持人開 `/study-control`，參與者只開以下對應分頁。主持控制不出現在參與者 UI；這是測試環境的版面隔離，不是權限授予介面。HTTP 只監聽當次隨機 loopback port，POST 拒絕其他 Origin、額外欄位與非白名單操作；所有控制只改記憶體。執行一名參與者的一項情境後先重設，再重新載入參與者分頁，避免上一輪欄位、未決回應或計數影響下一輪。

| 情境 | 參與者分頁 | 主持準備／控制 |
| --- | --- | --- |
| T01 | `/setup` | 辨認入口，沒有真配對連結 |
| T02／T03 | `/approvals?study=1&count=10` | 每次重新載入；兩個長名稱專案、獨立請求 ID；單次命令與有限期 shell 樣本 |
| T04 | `/widget?study=1` | 成果重設後重新載入；先讀歷史 diff／命令／圖片，再更新文字檔或圖片版本 |
| T05 | `/panel-http?study=1` | HTTP 重設後重新載入；設定「下次未決」，參與者決策一次，再新增不相關請求，最後確認未決 |
| T06 | `/panel-http?study=1` | HTTP 重設後重新載入；設定延遲 catalog，參與者開工具清單；觀測延遲數為 1 才中斷串流，送回失敗，最後恢復 |
| T07 人工整理 | `/study-material?material=alpha` 或 `beta` | 展開來源材料，自行填空白摘要；換資料組前重新載入 |
| T07／T08 H1 | `/handoff?study=alpha` 或 `beta` | 重設對應資料組；審閱後改檔、來源未完成或缺少檔案各獨立執行 |

人工整理與 H1 的來源事實、檔案內容及版本取自同一份 [alpha／beta 材料](../../tests/handoff-study-materials.ts)。H1 欄位不預填；主持人的預期答案不直接提供給參與者。摘要需保留兩項完成事項與未驗證事項，不能只匯出目標／下一步。T07 的 A 階段在審閱與具複製資格停止，停止來源與原生權限勾選只代表該合成情境的假設，不計為原生核對或真剪貼簿成功。

T06 中斷串流後，正式側欄可能已取消在途 catalog 查詢。若延遲數由 1 回到 0，記「查詢已取消」，不能寫成晚到失敗已抵達 UI；仍觀察上次快照、停用與恢復行為。未取消查詢的 HTTP 失敗抵達，由 transport 失敗案例另驗。服務恢復後可能自動取得新快照，不要求測試者重複點已消失的復原入口。

T08 的版本變更應能經重新核對及審閱恢復；來源 pending 仍不可準備。缺少支持檔案令基準 `complete=false`，來源真正裁切才使用 `itemsTruncated`／`textTruncated`，兩種缺漏分開記錄。未選入或不能支持的相對路徑維持未知，不能填合成版本湊完整。

材料限制：HTTP body 上限 4,096 bytes，只涵蓋本輪小型合成資料，不代表完整 schema 最大輸入。Workbench 圖片採透明 1×1 PNG 與固定合成 descriptor，版本 ID 亦為合成值；只測入口與歷史／目前身份判斷，不測圖片品質、真檔案 hash 或尺寸一致性。H1 文字檔則以確切 UTF-8 字串的 SHA-256／bytes 建立固定材料。主持更新後，等待參與者取得新狀態再繼續，不能把主持按鈕回覆當成參與者已看到版本變化。

## 3. 主持腳本與成功定義

任務文字讀一次。卡住時先記錄，再給中性提示「請依畫面找下一步」；需要指出控件位置才算有協助。完成後再問判斷題，避免問題本身教會答案。拒絕、停止或指出未知都可能是正確行為，不將按下允許當成成功。

| 編號 | 對測試者說的任務 | 主持人情境 | 成功與計時 |
| --- | --- | --- | --- |
| T01 | 「請找到開始連接的下一步。」 | A 使用 `/setup` 辨認入口；B 才貼允許的測試連結 | 至少四人無位置提示找到正確動作。A 不計連接成功；B 從可操作起到新快照可見 |
| T02 | 「請找出這個專案需要確認的操作，說明你會允許還是拒絕。」 | 十件請求、兩個長名稱專案，只給目標名稱 | 10 秒內開啟正確請求；操作前能指出 argv、cwd、範圍與期限。不得誤選另一專案 |
| T03 | 「完成這一次命令核准，再判斷目前能做什麼。」 | 單次命令與 shell grant 的合成樣本 | 至少四人說出一次請求與有效範圍內後續終端操作的差異；不把專案篩選當權限變更 |
| T04 | 「請找出最近工作的成果，判斷是否適用目前檔案。」 | diff、exit 0、歷史圖片，接著切換／更新來源 | 兩個主要導覽動作內開啟成果；能區分歷史版本與目前檔案。不得因 exit 0 或預覽成功就聲稱目前檔案已驗證 |
| T05 | 「剛才的核准沒有明確回應，請決定下一步。」 | `/panel-http` 的未決回應，list 仍 pending，再送不相關 SSE | 只查詢／等待，不再允許或拒絕同一未決請求；變更計數保持 1。狀態確定後才依新狀態操作 |
| T06 | 「連線中斷了，請確認現在能判斷哪些事。」 | SSE EOF、晚到的 catalog failure，再恢復連線 | 辨識上次快照、找唯一恢復入口；不將舊畫面當目前可操作狀態，不重送副作用 |
| T07 | 「請將這項工作準備給下一個 Agent 接續。」 | H1 合成來源與相關檔案；B 才操作真剪貼簿／ChatGPT | 從來源可操作到摘要已審閱且具複製資格，五次至少四次不超過兩分鐘；包含目標、下一步、相關版本與未確定事項 |
| T08 | 「來源或檔案有變，請決定是否仍能接續。」 | 審閱後改檔、來源 pending、基準缺漏三個變體 | 指出需重新核對或不能複製；不把人工停止當排他證明；區分基準不完整與來源裁切 |

T02 的十秒只衡量找到請求，不是完整審閱時間。T07 的兩分鐘只衡量準備上下文，不包括 ChatGPT 回答或工程執行；另記複製到人工送出、接收端首次對帳的時間。

B 階段由人貼上、送出摘要。接收端先核對 workspace 與支持的相對文字檔版本，記是否發現預置差異。Desktop 的「已複製」不能判成送出、接手或核對完成。環境不支持的版本讀取記未知，不新增 shell 操作補答案。

## 4. 無障礙與窄版專項

這組結果獨立於 T01～T08，不用工程 CSS 檢查替代。

| 情境 | 觀察與記錄 |
| --- | --- |
| 360／400／480px、長名稱、十件核准 | 必要入口與文字可讀；全名可取得；沒有兩個主要捲動區爭奪操作 |
| 真正瀏覽器 200% | 長 argv／diff 可檢視，主控件不被擠出；B 執行，iframe scale 只算合成檢查 |
| 只用鍵盤 | 詳情開關、返回原焦點、工具搜尋、取消；無焦點陷阱或必須滑鼠的入口 |
| 螢幕閱讀器 | 件數、連線變化與 unknown 各公告一次；切換不讀舊成果；狀態與錯誤不互相淹沒 |
| Reduced motion | 必要資訊不依賴動畫；停用動態不損失焦點或進度判斷 |
| 對比與字級 | 量測必要狀態、disabled／focus、權限與內容；核心判斷文字至少 14px。保留顏色、背景與狀態 |

記錄是否需要重讀、找第二句解釋或在同義狀態間猶豫。發現重複文字，優先合併狀態與動作，不以增加常駐說明作為預設解法。

## 5. 記錄範本

每次使用一列，先記開始條件。時間只填實際觀察；未執行填「未測」，不能補零。匿名代碼不與姓名、帳號或原對話 ID 一起提交。

| 編號／資料組 | 階段／版本 | 任務 | 秒數 | 主要動作數 | 協助 | 結果 | 誤判／卡點 | 嚴重性 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 未填 | 未填 | 未測 | 未測 | 未測 | 未測 | 未測 | 未測 | 未測 |

另記 T05 變更數、T07 必要資訊完整性、T08 是否識別差異。H1 與人工整理以個別 paired 結果呈現秒數、缺項及重新說明次數。五筆資料只作方向判斷，不宣稱統計顯著或全體使用者成效。

嚴重性：誤核准、誤認未知已完成、分享未審閱資料為阻擋；找不到必要入口或不能恢復為高；多一步、重複或需要重讀為一般。遇阻擋就停止該情境，其他獨立旅程可繼續。

## 6. 品質與 H2 決策

已發現的誤核准、重送副作用或誤認版本等阻擋問題，發布前必須修正。原生、宿主、鍵盤、200% 與讀屏各需自己的證據；若未測，就記錄限制。正式多人研究另行安排，不要求一般使用者招募或跑完整腳本；五次成功也不覆蓋漏測平台。

有實際接續需求，且人工複製持續造成漏項或無法接續時，再依日常回饋或選用研究評估 H2。慢在整理或理解就先改善 H1。版本差異、來源仍工作、權限不清楚不以自動分享解決。

目前執行狀態維持「未測」。後續報告填入記錄與環境，連回[交接規格](handoff-spec.md)及[開發計畫](development-plan.md)，不修改歷史研究資料來假造已達標。

## 7. 工程準備紀錄
